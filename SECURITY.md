# Security reporting — private pilot

Status: source policy updated 16 October 2026. The project owner is the maintainer and selected **[demirakbal@gmail.com](mailto:demirakbal@gmail.com)** for private security reports. This records the chosen destination; mailbox delivery/response has not been tested. This file does not enable GitHub private vulnerability reporting or promise a response time.

Send a minimal sanitized security report to the address above. Do not post credentials, private profiles, personal records, exploit payloads containing real data or full account logs in a public issue, pull request or discussion. Email is not a reason to include secret values or unnecessary personal data; ask the maintainer for an appropriate transfer method if more sensitive evidence is necessary.

## Useful report content

In a report to the selected security address, provide only the affected plugin/source version and host context, expected versus actual boundary, minimal sanitized steps, relevant source locator, plausible impact and whether the issue is observed or a hypothesis. Synthetic examples are preferred. Do not include secret values, a complete profile/mailbox, third-party personal data or an unnecessary full transcript. A disclosure report does not authorize testing another person's service/account or changing production data.

The maintainer should acknowledge through the selected channel, establish scope/version and handle access to the report, preserve evidence, investigate proportionately and coordinate any applicable fix/disclosure. Timelines, ownership and disclosure terms must be agreed for the real project; no bounty, guaranteed response, confidentiality guarantee or legal safe-harbor promise is made by this draft. External notification, credential rotation and account changes require their own actual authority.

The current pilot has one coordinator and 25 specialists plus optional helper/check source. Source inspection and historical installation/test evidence do not certify permission enforcement, privacy, dependency security or every client. See the roadmap, support matrix and licensing record for actual limitations. Configuration concerns belong to agent-configuration-review; substantive application vulnerabilities use the available appropriate security workflow only when requested. No scanner or automatic test campaign is activated by a report or this policy.

Before public release, review supported versions/handling expectations and reconcile any hosting/platform reporting settings with this selected contact. Destination selection is source evidence only; no delivery or response guarantee is claimed. This source change sends no message, opens no issue, configures no service and performs no vulnerability test.
