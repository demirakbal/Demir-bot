# Contributing and maintaining

This is a private development pilot. Read AGENTS.md and the existing owner before editing. Work in canonical `plugins/demir-bot-pilot/` source, preserve unrelated changes and keep `demir-bot-pilot` identity stable. See docs/licensing.md before proposing public redistribution; contributing source does not settle rights or grant publication authority.

## Change the existing owner first

Identify the actual trigger/outcome and gap. Prefer a focused extension to the existing specialist/reference over another coordinator, copied rule or duplicate provider. The coordinator owns routing/shared execution scope, specialist references own domain procedures, private profile owns facts/machine settings, and roadmap/README/RESOURCES own scope/entry/inventory. Link shared policy rather than appending conflicting copies. Use current source and preserve approved behavior; hypothetical new capability is not an observed failure.

For a genuinely distinct new skill, establish its unique positive/negative triggers, input/output/permission contract and why existing composition is insufficient. Inspect actual host-authoring requirements, then reconcile SKILL.md, relative references, client metadata, namespaced route, licence/provenance, expected skill inventory and affected counts deliberately. Do not auto-regenerate an expected inventory to accept accidental directories. A skill name or metadata record does not prove discovery or behavior. Current batch adds references/tools, retaining 26 skills.

## Source, dependencies and examples

Preserve scoped pre-edit content in approved history/private rollback storage, including uncommitted work. Keep private profiles, credentials, correspondence, course documents, model/provider data, runtime queues, indexes and backups out of source and fixtures. New examples must be synthetic and distinguish expected output from recorded execution. Retain complete upstream notices and source/version/fingerprint/adaptation history at the existing owner. Do not run downloaded source, install dependencies, change global configuration or import another host's hooks incidentally.

Inspect changed source and meaningful neighboring contracts, paths and links directly. Testing is opt-in: writing, running, fixing and rerunning are separate scopes. Never start tests/builds/linters, model evaluations, docs generators or preview/device workflows as automatic completion steps. Existing mandatory release gates remain unmet when execution is unapproved; do not disable them. The inactive CI example is not an invitation to enable Actions. No automatic reviewer or worker delegation.

## Reconcile and deliver

Update only affected README/setup/contracts, RESOURCES links, roadmap state and Unreleased notes. Preserve historical source/install/test records with their exact snapshot/date. Report concrete changes, item elapsed time when requested, missing requirements and unverified behavior. Source presence, installation equality, index freshness, native discovery, authenticated operations and release acceptance are independent evidence categories. Do not claim cost/reliability gains without comparable observations.

For requested Git publication, use the existing Git specialist, explicit owned hunks and whole outgoing range/privacy review; ordinary edits do not authorize staging, commits, pushes, PRs or releases. External messages/account changes require their actual authority. Do not add maintainers, owners, branch protection or funding links without the responsible user's decision.

For a requested local refresh, follow installation.md and update-and-recovery.md: confirm the existing marketplace source, update source metadata only as needed, reinstall through the supported host and report the actual returned/comparison/discovery evidence. Never edit generated cache files or reinstall a standalone duplicate. QMD refresh requires the exact current collection authority in the coordinator's skill-sync.md; respect exclusions and do not widen the index. Cloud sync stays deferred, with no export/watcher/background retry. No private-profile modification is implied by plugin maintenance.

Acceptance example: add one focused reference at an existing owner, link it, record source-only status and leave installation/indexing pending where unauthorized. No-action case: an unrelated small fix does not create a skill, ADR, test suite, public release or maintenance service. The current guide was saved without a contributor workflow run or remote change.
