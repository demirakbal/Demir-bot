# Confidentiality before distribution

Use for a named outgoing candidate and destination. Reuse this skill's data-flow analysis, agent-configuration review for executable access and release readiness for artifact/environment gates. Identify exactly what would leave the machine: repository range, package/archive, generated media/PDF, metadata, documentation/examples, website source or provider upload. A clean working tree or ignore rule is not proof that an outgoing artifact/history contains no private content.

Keep machine-specific private exclusion terms and personal records in their approved private owner outside Git and public test fixtures. Inspect only the relevant rules; never copy a private deny list, path inventory, biography, account IDs or transcript into a public report. General exclusion categories may be documented. Use synthetic examples and minimize diagnostic output. Renaming a person/project cannot sanitize private facts, screenshots, document metadata or embedded identifiers by itself.

Inspect the actual candidate contents and relevant outgoing history, including generated files, attachments, comments, manifests, screenshots, caches, indexes and backup/runtime files if present. Match scope to what is actually distributed; a package-only inspection cannot certify repository history or the published site. Preserve licence/provenance notices. Inspect archive member names/content only when an actual archive exists; never assert archive safety from source filenames alone. No scanning tool, build or generated export is implicitly authorized by this gate.

Record inspected version/surface, findings and uninspected boundaries without echoing sensitive values. Source exclusions, actual absence from a candidate, installed state, remote visibility and history removal are distinct claims. A candidate with an unresolved confidentiality issue remains blocked. Correct only the authorized source/artifact; credential rotation, remote deletion, contacting recipients and rewriting history need their applicable exact scope. Source deletion cannot recall existing downloads or remote caches.

Acceptance example: a selected package includes only portable guidance and synthetic examples while private profiles/runtime data stay external; inspection names the exact package and unreviewed history. No-action case: internal maintenance does not upload the checkout to a scanner or publish a “safe” badge. A saved procedure is not a completed release audit. Current work adds the gate and corrects affected metadata; no immutable public candidate, archive/history audit or remote cleanup is claimed.
