# Adaptation and capability evidence

Reviewed 2026-09-21. Adapted selectively from Alireza Rezvani's MIT-licensed LinkedIn suite v1.0.0, metadata updated 2026-08-25:
https://github.com/alirezarezvani/claude-skills/tree/main/marketing/linkedin

Actual instructions inspected, not just catalogue descriptions:
- skills/linkedin-skills/SKILL.md: five-lane routing, evidence and action boundaries.
- skills/linkedin-profile/SKILL.md: credible positioning and inspectable proof.
- skills/linkedin-strategy/SKILL.md: sustainable audience-focused planning.
- skills/linkedin-content/SKILL.md: substance-led format, factual integrity, accessibility.
- skills/linkedin-engagement/SKILL.md: specific individual relationships and useful comments.
- skills/linkedin-analytics/SKILL.md: descriptive statistics, confounds and cautious interpretation.

The inspected instructions call bundled Python scripts; the suite describes 17 standard-library scripts and no account credentials/API. We did not import or execute them, verify their implementation, or install the suite's agents. This adaptation has no script/runtime dependency. Web research requires an available research tool; publishing requires supported authenticated action access; shared personalization depends on the sibling personal-writing reference.

Retained: distinct lanes, truthful proof, sustainable effort, substantive engagement, accessibility and honest analytics. Changed: automatic relevant routing without forced handoffs/interviews, no default fork/delegation, no numeric scoring or mandatory lint/test loops, no rigid quotas or sample-size guarantees, follower growth retained as one of Demir's goals, conditional approval-based publishing, and shared approved voice/facts. Added date-aware CS/data science/AI research and exact-action approval with duplicate prevention.

Rejected as universal facts: links must go in the first comment; fixed mobile folds; fixed "safe" outreach limits; unsupported algorithm guarantees; blanket assertion that every API posting workflow is prohibited. Check current platform limits and policies when material rather than inheriting static upstream claims.

Official capability evidence: LinkedIn's Share on LinkedIn documentation describes authenticated member publishing with OAuth and w_member_social:
https://learn.microsoft.com/en-us/linkedin/consumer/integrations/self-serve/share-on-linkedin
This is capability documentation, not proof of Demir's authorization or a configured connector. On this session's tool inventory, only name-based LinkedIn people search was exposed. Plugin discovery did not establish a publishing integration. Cloud skill synchronization remains deferred.
