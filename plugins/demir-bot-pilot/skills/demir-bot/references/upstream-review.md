# On-demand upstream review

Use for an explicitly requested update or a concrete source gap. Reuse `capability-maintenance.md` and the existing `upstream-adaptations.md` provenance owner. Select the implicated upstream files, inspect license/dependencies and preserve intentional local differences. A changed digest establishes different bytes, not a defect or an approved update.

`tools/upstream_fingerprint.py` is a standard-library, read-only helper for already obtained local source files. It accepts an absolute `--root`, one or more explicit `--file` relative paths (up to 100, each at most 2 MiB) and an optional `--compare` prior JSON snapshot. It prints schema-1 SHA-256/size records and new/changed/unchanged/not-selected comparisons to stdout. It performs no fetch, file write, import of selected source, package installation or command execution. A missing/unsafe/oversized input or malformed baseline returns a sanitized error and exit 2, without a partial success snapshot. A prior file omitted from the selected scope is “not-selected,” not deleted. Source-only implementation: this helper has not been run.

Read explicit non-private source selections only. A digest is not anonymous metadata, authenticity proof or a license grant; snapshots need their own approved storage/destination. The helper rejects symlink components below the root but is not a hostile-filesystem sandbox or race-proof reader. Review stable trusted local copies; do not use it to inspect a changing untrusted tree. It does not validate remote signatures or attest to runtime behavior.

For each changed candidate, compare old reviewed upstream, new upstream and the local adaptation using available source/diff inspection. Classify retained behavior, relevant improvement, conflicting permission/default, dependency/license change and unknown effects. Record keep/update/merge/retire with the exact reason and unresolved evidence. Merge useful changes at the canonical owner rather than replacing the whole skill. Preserve license notices and local opt-in/privacy/approval rules. Retirement remains a proposal until deletion/uninstallation is authorized.

Acceptance example: a changed upstream default introduces automatic tests; retain Demir's opt-in rule while considering the independently useful source change. Identical bytes need no repetitive re-review unless other dependencies changed. No-action case: ordinary app implementation does not start an upstream stocktake. No watcher, automatic download/import, installed-skill removal or usage scoring is introduced. Actual update review still needs the selected upstream versions; fingerprints do not supply them.
