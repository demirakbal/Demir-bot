# Read-only installation doctor

Use for a requested scoped local source/cache inspection, not on every task or after each edit. `tools/installation_doctor.py` accepts an explicit absolute `--source` plugin directory and optional absolute `--installed` directory. It reads regular source files, compares filename/content hashes, reports local manifest name/version and portable identity agreement, skill/metadata presence and a source snapshot. Missing/extra/changed files are distinct. It never calls Codex, QMD, a shell, credential helper, package manager or provider, and never writes, repairs, installs or indexes anything.

The helper is source only and **NOT RUN**. It does not certify the host schema, all links/routes, semantic instruction correctness, installation registration or effective discovery. Those require their actual evidence. Metadata presence cannot establish activation. Optional-tool availability/authentication and behavior stay uninspected/unverified; the doctor does not probe accounts or read a private profile. Reuse existing structural checks only under separate execution authority, rather than pretending this narrow tool replaces them.

Limits: at most 2,000 files, 6,000 visited entries, 2 MiB per file and 20 MiB total. It rejects encountered symlinks/nonregular entries and malformed/duplicate-key JSON, emitting a sanitized error with exit 2 and no partial success report. A valid inspection returns exit 0 even when differences are found: inspect the explicit difference/state fields. These are trusted, stable, explicitly selected plugin trees; this is not a hostile-filesystem sandbox or race-proof reader. Ancestor aliases and concurrent replacements are outside its guarantee. Filenames/hashes can be sensitive: select only portable source/cache roots and keep the output private unless sharing is authorized.

An optional `--qmd-evidence` file may contain exactly `collection`, `source_snapshot`, `indexed_at` (timezone-bearing ISO date) and `documents` (integer count). It compares the supplied source snapshot only; live index state and collection scope coverage always remain unverified. Do not invent a matching snapshot or call that supplied record a fresh QMD query. The snapshot algorithm is SHA-256 of compact sorted JSON mapping package-relative file names to SHA-256 values, matching the local structural inventory convention. A collection can intentionally exclude some source; a package hash mismatch alone does not identify which indexed entries are stale.

Acceptance example: selected source/cache bytes differ, so the report names changed files and suggests the supported refresh as a separate operation. A missing cache leaves installed state not provided; it must not report a successful install. No-action case: reading a skill needs no doctor run. Recovery is a reviewable proposal: identify canonical source/registration, preserve unrelated work, then perform only an authorized supported refresh/repair. Never edit installed caches, reconnect accounts or silently rebuild an index.
