# Private profile boundary

Resolve an explicitly supplied profile directory first, then a configured DEMIR_BOT_PROFILE_DIR, otherwise `demir-bot-private` under the current CODEX_HOME (default `~/.codex`). These are path conventions; use the actual host/home, never another user's absolute path. Do not search other users' profiles or enumerate environment secrets. Explicit task instructions override saved preferences.

Read preferences.md once when using the coordinator; load only relevant files thereafter: facts.md for approved personal claims and restrictions, tones/<channel>.md for channel voice, projects.md for project context, capabilities.md for operation-specific evidence, local-setup.md for local commands and cloud deferrals. On updates write the canonical private file, not a copy in the skill. If absent or inaccessible, use current user context; do not infer Demir's identity, biography, accounts or tone for a different user, or create a profile without authorization.

The private profile is outside skill packages and their QMD collection. Never bundle it, follow its pointers into an export, index it, upload it or migrate it to cloud as part of plugin packaging. Keep local directories owner-only and files owner-readable/writable. This boundary is a storage convention, not encryption or enforced multi-user isolation. Backups and old indexes may still contain historical copies; do not claim removal from them without evidence.

The pilot keeps all 22 skills as sibling directories under skills/. Resolve a bare bundled skill name to demir-bot-pilot:<skill-name> in the current catalogue, then locate that skill's SKILL.md and references. Do not select the standalone copy when using this pilot. Relative ../ sibling paths preserve the same layout after installation; references inside a reference document resolve from that document unless explicitly described as skill-root or skills-root paths. A missing bundled file is a package limitation, not permission to import another version. Discovery of the original 21 skills has been observed; automatic routing and fresh-client discovery of later additions remain untested until actually observed.

Authorized future package edits target the local source plugin identified in the private capability record, not a generated plugin cache. Preserve rollback and use the supported local-plugin update/reinstall flow only when requested. Do not change standalone copies or export private data as an incidental part of a pilot update. Public redistribution and license compatibility require separate review.
