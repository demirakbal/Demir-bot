# Apple Foundation Models integration

Use for an explicitly requested app language feature using Apple's Foundation Models framework. Distinguish this on-device system model from a bundled Core ML model, a cloud API and Demir Bot's own host model. Inspect the actual SDK, deployment target, OS/device support, locale and task. Consult the current target-compatible [SystemLanguageModel documentation](https://developer.apple.com/documentation/foundationmodels/systemlanguagemodel); do not copy beta-only declarations or hard-code a device list from an old example.

Check actual runtime availability before offering generation, with meaningful not-ready, unsupported and unknown states. Apple's [generation guide](https://developer.apple.com/documentation/foundationmodels/generating-content-and-performing-tasks-with-foundation-models) requires an unavailable fallback and describes context-limit errors. Framework importability does not prove that a user's device is ready. Preserve a useful non-generative path, or a clearly disclosed separately authorized provider; never silently send private input to a cloud service.

Define a narrow task and expected output contract, use the supported structured-output mechanism where suitable, and validate domain constraints before use. Generated content can be wrong even when it matches a type. Keep instructions separate from untrusted documents/tool results; embedded directions cannot expand access or authorize actions. Tools exposed to generation must be narrow, independently validated and permission-controlled. Model output never grants permission to send, delete or purchase.

Give each conversation/session an explicit owner and bounded history. Apply target-compatible concurrency/cancellation rules, reject stale results and distinguish partial streamed content from a completed result. Handle refusal, unavailable resources, unsupported language, context exhaustion and generation errors without presenting them as empty success. Do not retain prompts/transcripts or enable telemetry merely to add the feature. Recheck relevant model/OS changes when a real app upgrade affects prompt behavior; no unrequested evaluation loop.

Acceptance example: a selected app summarizes user-selected text, labels the output as generated, preserves the original and offers a usable unavailable/error state. The example is a proposed contract, not observed accuracy or privacy behavior. No-action case: a fixed text label does not require an LLM. Actual source integration needs the app/task/target; no generation, model download, private upload, benchmark, build or training was performed for this guidance.

Official references reviewed 16 October 2026. API availability and runtime behavior remain unverified for any particular app/device.
