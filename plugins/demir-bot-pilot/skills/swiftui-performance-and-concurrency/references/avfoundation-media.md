# AVFoundation media workflows

Use for a requested capture, playback, composition or export feature in a named app. Identify the actual operation, source ownership/rights, input format, target SDK/deployment, output destination and existing media service. Keep these operations separate: playback does not require camera access, and editing a source recipe does not authorize recording or exporting private media. Consult current documentation for the exact API family before prescribing syntax or deprecated callback replacements.

For capture, identify camera/microphone/photo-library permissions actually needed, provide useful denial/restriction states and request access at the relevant interaction. Give session configuration, start/stop and sample processing one supported serialized owner; keep blocking configuration away from UI-critical work. Bound frame/audio queues, handle interruptions/unavailable devices, and stop capture when its user-owned lifetime ends. Do not retain or upload recordings by default.

For playback, distinguish ready/buffering/waiting/failed/ended states, observer/task ownership and user intent. Remove periodic observers/subscriptions when the player owner ends. Apple's [audio interruption guide](https://developer.apple.com/documentation/avfaudio/handling-audio-interruptions) distinguishes interruption begin/end and possible resumption; do not force playback after the user paused or a route became inappropriate. Choose audio category/mode/options for the actual experience and supported platform, preserving other audio where intended.

For composition/export, preserve timing, track selection, orientation/transform, dimensions, color/HDR, audio and captions required by the brief. Check actual asset/preset/file-type compatibility; a filename extension alone does not select an encoder. [AVAssetExportSession](https://developer.apple.com/documentation/avfoundation/avassetexportsession) defines an export configuration, and the supported [async export contract](https://developer.apple.com/documentation/avfoundation/avassetexportsession/export(to:as:isolation:)) defines completion/cancellation. Use target-compatible APIs and keep progress separate from successful completion. Write only to an authorized destination, preserve existing output, bound temporary storage and clean up only owned partial files. Never delete a supplied original as export recovery.

Acceptance example: a selected app stops recording on user request, handles interruption and exports a new compatible file without overwriting its source. Format/playback claims require inspection within authorized preview/run scope. No-action case: changing player controls does not start capture or transcode a library. The current item saves guidance; no media access, permission prompt, playback, export, build or device operation occurred. Actual implementation needs the app and media/output contract.
