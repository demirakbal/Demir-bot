# Media, motion and visual-asset delivery

Use for a requested animation, UI demo, icon/image asset, video adaptation or inspection of supplied creative source. Establish the actual deliverable, audience/use, source assets/rights, duration or interaction timeline, dimensions/aspect, readable text, audio/captions, file format and output destination. Reuse existing project tokens and the selected available media/design provider before adding another runtime. A source brief does not authorize spending, uploading private assets or publication.

## Choose the actual mechanism

For a local UI interaction, use its existing framework and reduced-motion contract rather than render a movie. For an icon/static graphic, preserve needed size, contrast and meaningful text alternatives; choose editable/vector or raster output according to the requested use and actual tooling. For mathematical/code-driven animation, Manim or Remotion is only a candidate when that source/runtime is selected. Blender inspection needs the supplied project and actual supported reader; VideoDB or another hosted workflow needs a real provider operation contract and account/data scope. Do not claim any candidate is installed from its name or silently install render dependencies.

## Timeline recipe

Declare a concrete timeline in seconds or frames, with an explicit frame rate only when frame-based output needs it. Each track names source/element, start/end, initial/final state, interpolation, overlaps and final readable hold. Keep text/audio timing and shared counters on one timeline. Distinguish an intentional cut from interpolation; avoid simultaneous changes that obscure meaning. A recipe is not a rendered result.

Synthetic example: a selected 6-second title card can use 0–0.4 seconds for a subtle text entrance, 0.4–5.5 for a stable readable title, and 5.5–6 for exit. This is a proposed timing example, not measured legibility or generated footage. An interactive UI version preserves the information and uses a static/reduced-motion presentation when requested or supported by the user's preference. Avoid flashing, forced autoplay, motion-only status and inaccessible essential interactions; retain the existing frontend accessibility owner.

## Assets, generation and evidence

Confirm permitted logos, people/voice/likeness, music/fonts, supplied footage and destination rights before their actual use. Use synthetic placeholders when writing reusable examples; do not copy private documents into distributable assets or manufacture endorsements. For taste calibration, use the user's approved references and describe specific layout, typography, color and motion choices; do not infer permanent preference or copy an unrelated creator's identity/style samples as personal facts.

For a selected tool/provider, inspect actual input/output constraints, costs, account identity, asset upload, cancellation, retry and export behavior before implementation. A generation timeout can leave a paid job active: reconcile status instead of resubmitting blindly. Distinguish source prepared, job submitted, render completed, exported file inspected and published. None proves device/browser playback or interaction behavior without that observation. Do not mark a preview/script as finished video.

Deliver the requested source/artifact and concise limits. Inspect actual format/duration/dimensions/readability only within authorized preview/run scope; tests/builds/render loops remain separate. A source change alone does not authorize creating a demo library, hosting it or publishing. No-action case: editing button text does not start a video workflow. Current item saves procedures/recipes; real media production remains pending the actual brief, assets and chosen tool.
