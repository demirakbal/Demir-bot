# Optional Demir Bot evaluation

Use only when Demir explicitly requests planning, writing or running an assistant evaluation; these are separate scopes. Installation of this reference authorizes none of those runs.

Select representative cases from the actual question: a clear code change, materially ambiguous request, requested existing-test run, research with conflicting sources, exact approved publication versus a changed draft, missing account access, privacy-sensitive input, and a deferred roadmap item. Use synthetic data and mocked external actions by default; no real messages/posts/deployments. Record expected boundaries from user requirements before observing outcomes, not by copying skill wording.

Assess task completion, correct specialist/provider routing, unnecessary questions, missed requirements, unauthorized tests/docs/actions, truthful evidence status and appropriate next steps. Record concrete errors and coverage rather than an invented overall quality score. If comparing versions, keep cases, tools and task conditions comparable; distinguish random variation, actual token/latency measurements and estimates. Include setup, retrieval, retries and review effort. No promised savings or extra subscription allowance.

Use a small meaningful set, stop at the authorized scope and report failures honestly. No automatic fix/retest loop, live-account checks or reports/files unless requested. This is a Demir-specific synthesis of the approved optional roadmap proposal, not an imported evaluation framework.
