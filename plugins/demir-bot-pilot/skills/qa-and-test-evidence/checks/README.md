# Structural package checks — roadmap 085

Execution evidence is snapshot-specific; consult the retained acceptance report for actual runs. This suite extends qa-and-test-evidence; it adds no skill, hook, CI job or automatic validation. Run only with explicit execution authorization. Installation is a separate action; no dependencies were installed while authoring this suite.

## Tooling and authorized invocation

Reference interpreter: CPython 3.11.11 (`.python-version`). Exact parser/validator dependencies, including their dependency closure, are in `requirements.txt`. Resolve these into an isolated environment only when installation is authorized. Existing host interpreters and dependencies have not been established as matching these pins. Missing PyYAML previously blocked a standalone validator; this suite declares it explicitly instead of assuming availability. No vendored host validator or authoritative host schema was found in the inspected repository. These pins have not been execution-verified together; platform wheel availability remains unverified. The file is version-pinned, not a hash-locked supply-chain guarantee.

From this directory, using an already provisioned interpreter with those dependencies, separately authorized commands are:

```sh
PYTHONDONTWRITEBYTECODE=1 python -m unittest -v test_structural
PYTHONDONTWRITEBYTECODE=1 python structural.py
```

The first command defines 24 cases: 23 isolated synthetic contracts and one read-only acceptance case against the current package. It uses temporary synthetic directories and cleans them up. The second inspects current source and prints JSON to stdout; it writes no report. Neither command launches agents, subprocesses, network operations or provider calls. No retry loop is configured. Preserve the original failure output and distinguish dependency/import errors from assertion failures. Nonzero exit means failure; never describe an unexecuted case as passed. A rerun or fixes after a run require applicable scope.

## Contract and coverage

- `manifest.schema.json` is the **local skills-only package contract**, not OpenAI host-schema certification. It requires the existing identity, skill root and interface fields and rejects undeclared runtime/config fields. Schema changes need a reviewed package-contract decision; do not silently relax assertions to make a result green.
- `inventory.json` independently records the current 22 expected skill directories. Additions/removals must deliberately reconcile this list, actual skill files, agent metadata and count statements in the manifest. It is not an autogenerated baseline that accepts whatever exists.
- JSON and YAML reject duplicate mapping keys. Skill frontmatter requires a matching unique kebab-case name and nonempty description; agent metadata requires a display name; optional short_description/default_prompt fields must be nonempty strings when supplied, and a supplied prompt must contain its own complete namespaced route. Installed skill-authoring guidance (skill-creator/references/openai_yaml.md, inspected 2026-09-24) labels these fields optional; omission is not an invalid value. This is a bounded local metadata contract, not a full official agent schema.
- CommonMark inline/reference links and images are parsed, with package-relative file and Markdown heading-anchor resolution. Duplicate headings receive numeric suffixes. Absolute/escaping links and package symlinks are rejected without reading their destinations. External URLs are not fetched.
- Literal `demir-bot-pilot:<name>` routes in Markdown/YAML/JSON must name a packaged skill; the documented `skill-name` placeholder is excluded. External provider routes are not asserted installed. This checks target existence, not activation or instruction-conflict behavior.
- The source snapshot is SHA-256 of compact sorted JSON mapping package-relative filenames to file SHA-256 values. All ordinary package files are included; `__pycache__` is excluded. Symlinks/unreadable files fail and make the digest partial; do not call that an exact complete snapshot. Temporary fixtures, repository-external docs and the installed cache are not the evaluated source.

## Limits and retained evidence

Bare prose/backticked paths, reference-like examples, raw HTML anchors/links and host-specific heading-slug quirks are not comprehensively resolved. Private-profile pointers remain external inputs, never dependencies to copy into the package. External provider availability, licence compatibility, privacy guarantees, semantic instruction conflicts, installed-cache equality, runtime routing and behavioral reliability require different evidence. A local structural pass establishes none of them.

The current-source case deliberately may expose existing source defects. An acceptance result applies only to the recorded source snapshot, not later edits. Do not fix unrelated source or update inventory merely to suppress findings. Report each finding with its path, code and actual impact after an authorized run; distinguish limitations and false positives requiring contract review.
