# Troubleshooting and support

Start with the exact symptom, host/session and affected operation. Use existing source/returned evidence before another run. Preserve the original error with secrets/private content redacted; do not collect a whole home directory, profile, mailbox or account log. A source diagnosis does not establish runtime recovery. The configuration specialist's runtime-diagnostics.md owns deeper layer analysis.

| Symptom | Distinguish first | Smallest scoped response |
|---|---|---|
| Two same-named plugins | Stable ID/marketplace, source/version and local versus cloud registration | Select the intended identity; remove only the explicitly chosen duplicate through the supported host. Never delete both by display name. |
| Skill missing | Registration, canonical pointer, installed bytes, active session catalogue, actual client support | Inspect the selected boundary; refresh/reload only within authority. Don't install a standalone duplicate. |
| Old behavior after editing | Source versus installed copy versus loaded session versus index | Compare the affected source/version; don't claim editing source refreshes every copy. |
| Local file unavailable in another client | Actual filesystem visibility and approved shared source | Request/provide the necessary selected content through supported access; don't pretend the browser can read Mac paths. |
| Tool shown but operation denied | Tool exposure, authentication, resource permissions and operation-specific authorization | Keep the denied operation pending; no implicit login, role expansion or private-UI workaround. |
| QMD misses a recent change | Existing collection scope/exclusions, indexed version and embedding evidence | Identify the affected included source. Apply exact refresh authority; don't index profiles/backups or widen the collection silently. |
| CLI help warns about PATH aliases | Returned exit/result versus failed alias creation | Report the warning separately from useful help; don't change shell/global permissions or reinstall tools merely to suppress it. |
| Repeated/uncertain send or upload | Logical operation, dispatch attempts and provider receipt | Hold uncertain attempts and inspect authorized status evidence before retrying. No local receipt proves exactly-once delivery. |
| A model/agent seems to ignore a rule | Actual loaded owner, conflicting scope and supported host enforcement | Diagnose from evidence; don't infer hidden calls or launch a reviewer/evaluation loop automatically. |

The earlier duplicate cloud registration was removed under explicit direction, retaining the local personal plugin. That historical result does not replace inspecting actual current identities if a new duplication is reported. Cloud synchronization remains deferred; recreating another registration is not a troubleshooting default.

The optional installation doctor compares explicitly selected source/cache trees only when its run is authorized. Its source is currently unrun; it does not prove host registration/discovery, live QMD freshness, account access or all reference correctness. See [installation](installation.md), [update/recovery](update-and-recovery.md) and [support matrix](support-matrix.md) for their canonical boundaries. Do not run structural tests, builds, browser checks, scans or sample account actions simply to answer a support question.

For a report, include the candidate/source version, relevant host/OS/tool version if already known, expected/actual behavior, minimal sanitized steps, exact error stage and what was actually inspected/run. Unknown values are useful; invented evidence is not. Omit tokens, private profiles, transcripts, coursework documents, personal paths and recipient lists. Security-sensitive findings need the actual private reporting channel, not a public issue; no contact address or response-time promise is invented.

Acceptance example: a missing skill is traced to a stale selected cache and reported with a separate authorized refresh option; a permission denial stays denied. No-action case: a successful draft does not start an installation audit. Current guide is prepared source; no real support incident, account access, repair or diagnostic program was exercised.
