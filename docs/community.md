# Community and maintenance

Preparation scope confirmed by the project owner on 16 October 2026: a free GitHub project for developers and vibe coders, with the existing Demir Bot website and initial YouTube/Instagram channels. The project owner is the maintainer. Public distribution, licensing clearance, channel publication and account settings have not been completed by saving this guide. Documentation is English only for now.

## Getting help and proposing work

Read README.md, usage.md and troubleshooting.md before reporting a known setup issue. For a non-sensitive reproducible problem, use the prepared bug form with version/context, expected versus actual behavior and minimal synthetic evidence. For a capability proposal, describe the outcome, existing owner considered, concrete gap, acceptance/no-action example and actual dependency. A request is not a promise of implementation, a support response time or authority to run tests/accounts/services.

Use CONTRIBUTING.md and the PR template for a scoped change. The maintainer decides roadmap priority, compatibility, acceptance and releases, based on actual evidence and user scope. No team, steering group, automatic reviewer, bot triage, contributor scoring or CODEOWNERS assignment is required for this solo pilot. A contributor may suggest a new owner only for a distinct uncovered need; do not duplicate the coordinator or existing providers.

## Conduct and sensitive reports

Follow CODE_OF_CONDUCT.md in project spaces. Discuss behavior/source concretely, respect privacy and avoid harassment or personal attacks. Security-sensitive reports follow SECURITY.md and must not be placed in public issue forms. The selected private security contact is recorded in SECURITY.md; delivery has not been tested. A separate conduct-reporting route has not been specified, so do not assume the security address is approved for unrelated purposes or claim all public moderation arrangements are complete. The maintainer owns decisions; no automatic moderation or external messages are enabled.

## Channels and sustainability

GitHub is the intended source/adoption home; the existing website explains the project, and YouTube/Instagram can carry bounded educational content after release/rights gates. These are plans, not observed public account operations. Reuse approved source facts and channel tone; don't describe unverified runtime capability, success metrics or planned features as shipped. Publishing exact content/destinations remains separate from drafting.

No funding programme, donation link, paid support promise, mailing list, analytics collection or additional community service is selected now. Do not add FUNDING.yml or invent sponsor/account handles. Revisit only for a concrete user request. The project is planned as free distribution; that does not settle source/media rights or imply unlimited support.

Acceptance example: a user can propose a focused synthetic issue while the maintainer retains roadmap/release ownership and sensitive reports stay out of public threads. No-action case: a local source correction does not announce a release, invite users or create social accounts. Current delivery is community/governance preparation only; no public launch or community account change occurred.
