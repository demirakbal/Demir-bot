# Update, uninstall and rollback

These are separate operations. Reading this guide authorizes none of them; reuse the user's actual selected target/effect and existing authority. Preserve the canonical source, stable plugin identity and unrelated local work. Follow [installation](installation.md) for source registration/discovery and [release management](release-management.md) for version/candidate compatibility.

## Update the existing local registration

Inspect the active source pointer and current source/installed evidence. Preserve the actual pre-edit content using authorized version history or a scoped private rollback copy outside the index; HEAD is insufficient for uncommitted work. Edit canonical source, retain intentional adaptations/notices, reconcile affected metadata/docs, then refresh only when that installation operation is authorized. Use the supported add/reinstall operation documented in installation.md for this configured selector, with a source cachebuster only if the host requires it. Never patch generated caches or add a duplicate plugin to force freshness.

Inspect the returned identity/version/path and requested source/cache comparison separately from fresh-session discovery and runtime behavior. Keep QMD refresh explicit and scoped to its existing collection/exclusions; editing source or reinstalling alone does not establish index freshness. Cloud content, native profiles, PDF and published site have their own states. No automatic synchronization is introduced.

## Uninstall exactly the selected registration

Distinguish stable identity and marketplace from display name. In the existing configured local environment, the supported command described by local help is:

```sh
codex plugin remove demir-bot-pilot@personal --json
```

This is an example for a later authorized removal, not an action in this batch. The CLI describes uninstalling the selected plugin and removing its local cache. Inspect the real result/catalogue before claiming removal. Do not delete development source, private profiles, QMD data, owned cloud definitions, other registrations or a whole marketplace as incidental cleanup. Marketplace removal is a distinct command/effect and may affect other plugins; it is not a synonym for uninstalling one plugin.

## Recover or roll back narrowly

Identify the precise prior source/artifact and actual requested recovery. Compare the current affected files with the saved version before restoring, preserving subsequent work; reconcile conflicts rather than replacing the entire checkout. Reversing source does not roll back installed bytes, private records, index entries, cloud content or external publications. Reinstall a prior candidate only through a supported authorized flow after compatibility review; never copy old cache directories over a live installation by guesswork.

For partial/uncertain installation results, retain the original error/returned path and inspect the selected registration/copy before repeating a mutation. Permission denial is not permission to disable protections or change account scopes. If a required prior artifact is unavailable, report that limitation and propose a supported reconstruction as a new change, not a verified restoration. No global cache purge, profile reset, history rewrite or automatic retry loop.

Acceptance example: an authorized rollback restores one implicated instruction while retaining newer email-tone work, then reports installed/indexed state separately. No-action case: a stale answer does not immediately uninstall both same-named registrations. Current evidence: remove and marketplace-remove help inspected 16 October 2026, with the same nonfatal PATH-alias permission warning; neither removal operation nor rollback was performed. All real lifecycle scenarios remain unrun.
