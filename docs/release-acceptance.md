## Select the actual acceptance scope

Name the candidate/source revision or snapshot, audience/client/environment, intended distribution and required user-visible outcomes. Separate an instruction-source delivery from an installed private pilot, operational integration and public release. Use actual applicable requirements and existing project gates; do not invent a universal pass count or silently waive a required gate. Preserve accepted user deferrals. A missing run authorization leaves execution evidence unverified rather than starting a test loop.

For each applicable gate, record required/optional/not-applicable with its source, actual result or not-run/blocked state, artifact/environment and evidence locator. Keep source observation, historical result, inference, user-accepted risk and unresolved dependency distinct. “No source findings in the inspected scope” is not full runtime/security readiness. Use the existing QA gate and evidence owner rather than another scoring system.

## Recovery plan for a selected candidate

Identify the last usable source/artifact and scoped private pre-edit content, compatibility assumptions, changed settings/data, stop conditions, owner and supported restoration operation. Protect later unrelated edits. Source restoration, installed refresh, profile correction, index repair, server rollback and public recall are different effects. Inspect uncertain external outcomes before repeating writes; a failed local wait does not cancel remote publication. Never reset a private profile, delete indexes or rewrite history as incidental rollback.

If a candidate fails a required gate, hold that candidate, preserve the evidence and choose a scoped source correction or a clearly recorded deferral/narrower scope under actual user authority. Do not suppress failing assertions, fabricate a passing result or turn recovery into an endless fix/test/release loop. No recovery operation is authorized by drafting this plan.

Acceptance example: an instruction-source delivery can honestly report saved guidance and unrun runtime gates, while a public release remains blocked on its specific rights/confidentiality/support/legal requirements. No-action case: finishing one roadmap source item does not tag, upload, announce or deploy a candidate. Current delivery is this acceptance/recovery record; no candidate acceptance, installation, test, build or publication was performed.
