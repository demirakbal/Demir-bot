# Workflow cookbook

All examples are synthetic written walkthroughs, not observed runs. Each uses the existing coordinator and relevant specialist; no additional agent, provider or account is required merely to read it. See usage.md for ordinary request patterns and git-recipes.md for repository operations. Supply real sources for real work; do not claim an inaccessible assignment, paper or checkout was inspected.

## Coding: preserve valid zero

Input: an actual selected checkout and a reported function that incorrectly treats zero as missing. Request: “Inspect the caller/input contract and fix only that behavior. Don't write or run tests.” The coding route reads the relevant function and callers, distinguishes `0`, missing, empty and false according to the actual types, and saves a narrow correction. Expected output: changed behavior/source locator, preserved inputs and execution limits. Stop before unrelated cleanup, dependency installation, tests/builds, commit or deployment. Without the actual function/contract, explain the missing source rather than inventing a patch.

## Research: compare supplied papers

Input: two accessible papers, a specific question and comparison criteria. Request: “Compare their methods and evidence for this question; cite passages and include counterevidence.” The research owner inspects actual methods/results and distinguishes source claims, inference and inaccessible material. Expected output: a source-backed comparison, meaningful limitations and decision implications. Stop before an experiment, model evaluation or private upload. A citation snippet is not full-paper access and the example supplies no fabricated findings.

## University: one selected assignment part

Input: actual assignment/rubric, starter files and part 2 scope. Request: “Implement part 2, preserve lecturer text and explain the new functions. Write checks only if this part explicitly requires them.” The assignment planning/completion owners use actual criteria, retain starter behavior and track selected versus remaining parts. Expected output: scoped source and explanation with supplied/new work and unrun requirements separated. Stop before doing other parts, adding unrequested extras, executing checks/builds or packaging a knowingly incomplete final submission. If code-first teaching is requested instead, explain the actual source without editing.

## Writing: supplied professor-email facts

Synthetic input: “I attached my draft report and want feedback on whether section 2 is clear.” Request: “Write a short professor-email draft using only this fact; don't send.” Personal-writing selects email-tone and supplied approved facts. Expected output: a concise draft asking about section 2, without invented deadlines, prior meetings, grades or achievements. Stop at the draft; no mailbox search, saved external draft or send. No recipient address is needed merely to draft, and none is invented.

## LinkedIn: explain an approved project

Input: an actual approved project summary, audience and stated personal contribution. Request: “Draft a LinkedIn post from this source; mark unknown results and don't publish.” The LinkedIn owner reuses channel tone/facts and requests research only if the post makes current external claims. Expected output: a source-faithful draft with accurate contribution and no invented usage/performance. Stop before account access, scheduling, outreach or publication; exact final content/destination authority is separate. A project's planned feature is not described as shipped.

## Git: prepare a selected draft PR

Input: the actual checkout, selected changes, destination repository and base branch. Request: “Create a draft PR for these changes; don't merge.” The existing Git specialist preserves unrelated work, inspects the complete outgoing range and affected documentation/privacy, avoids a duplicate PR and publishes only within the clear requested scope. Expected output: observed branch/PR URL/state and evidence limits. Stop before merge/release, reviewer messaging, automatic tests or branch cleanup. If destination/required gates are unresolved, finish independent preparation and name the exact blocker.

For every walkthrough, distinguish expected behavior from observed source/tool outcomes. A chain can continue independent eligible cases while a target/access dependency is pending; it cannot fabricate that dependency or silently activate deferred work. None of these written examples grants authority to execute its operations.
